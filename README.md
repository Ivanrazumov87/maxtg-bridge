# Двусторонний мост MAX ⇄ Telegram (одна группа ⇄ одна группа)

> 📘 Полная инструкция по развёртыванию: [docs/DEPLOY.md](docs/DEPLOY.md)

Бот зеркалит сообщения между одной группой мессенджера **MAX** и одной обычной
группой **Telegram** — в обе стороны, как единый чат. Участники из разных
мессенджеров общаются друг с другом; к имени автора добавляется метка источника,
чтобы было видно, кто откуда пишет:

- в Telegram сообщение из MAX приходит как `Имя [MAX]: текст`;
- в MAX сообщение из Telegram приходит как `Имя [TG]: текст`.

> Используйте на свой страх и риск: MAX-сторона работает через неофициальный
> веб-протокол (аккаунт-пользователь, не бот), шанс блокировки аккаунта не нулевой.

## ✨ Возможности

- 🔄 **Двусторонняя** пересылка MAX ⇄ Telegram в реальном времени
- 🏷️ Метка источника `[MAX]` / `[TG]` в имени автора
- 📝 Текст, 📸 фото, 🎬 видео, 📎 файлы — в обе стороны
- 🎤 Голосовые: MAX → TG как полноценное голосовое; TG → MAX файлом со звуком
- 🛡️ **Защита от петли** (многослойная): метка источника + дедупликация по
  стабильному `message.id` (на диске, переживает перезапуск) + фильтр ботов
- 🚀 Промотка накопленной очереди Telegram при первом старте (старьё не
  вываливается в MAX задним числом)

## ⚠️ Ограничения

- Файлы из Telegram больше **20 МБ** боты скачивать не могут (лимит Bot API) —
  такие не пересылаются, отправитель получает предупреждение.
- Настоящее голосовое TG → MAX (с плеером-волной) через открытый протокол
  отправить не удалось — голосовое уходит файлом (звук воспроизводится).
- Стикеры и реакции пока не пересылаются.

## 🛠 Требования

- [Python 3.10+](https://www.python.org/downloads/)
- Аккаунт в [MAX](https://max.ru) (регистрация через мобильное приложение,
  затем можно пользоваться веб-версией)
- Бот в [Telegram](https://web.telegram.org) (создаётся через @BotFather)

## 📥 Установка

### 1. Зависимости

```
pip install -r requirements.txt
```

### 2. Токен MAX

Получите **отдельный** токен веб-сессии MAX: войдите на web.max.ru в окне
инкогнито, F12 → Application → Local Storage → значение `__oneme_auth_token`.
Этим токеном не должен больше никто пользоваться (подробности — в
[docs/DEPLOY.md](docs/DEPLOY.md), шаг 2).

### 3. Бот Telegram

1. В Telegram найдите **@BotFather**, отправьте `/newbot`, задайте имя и username.
2. Скопируйте выданный **токен**.
3. **Отключите privacy mode**, чтобы бот видел все сообщения группы:
   `/setprivacy` → выберите бота → **Disable**.

### 4. Группы

1. Создайте (или возьмите существующую) **обычную группу** Telegram и добавьте
   в неё бота (лучше — администратором).
2. Узнайте **ID группы Telegram**: перешлите боту
   [@my_id_bot](https://t.me/my_id_bot) любое сообщение из группы (начинается с `-100…`).
3. Узнайте **ID группы MAX**: откройте [web.max.ru](https://web.max.ru), зайдите
   в нужную группу — ID будет в адресной строке.

### 5. Конфигурация

Скопируйте `.env.example` в `.env` и заполните:

```
MAX_TOKEN=токен из шага 2
MAX_GROUP_ID=-…            # ID группы MAX (из адресной строки web.max.ru)
TG_BOT_TOKEN=токен из шага 3
TG_GROUP_ID=-100…          # ID группы Telegram
MONITOR_ID=                # необязательно: чат для уведомлений «встал/упал»
```

## 🚀 Запуск

```
python main.py
```

Если в консоли появилось имя вашего аккаунта MAX и `[bridge] Telegram poller
запущен` без ошибок — бот работает.

Для круглосуточной работы разверните на сервере (VPS) под systemd — готовый юнит
[deploy/maxtg.service](deploy/maxtg.service), пошагово — **[docs/DEPLOY.md](docs/DEPLOY.md)**
(там же диагностика и список мест в коде, которые нельзя «улучшать»).

## 🧩 Как это работает

- **MAX → TG:** входящее сообщение MAX (opcode 128) пересылается в группу
  Telegram; видео и голосовые резолвятся в URL отдельными запросами
  (opcode 83 / 301) и заливаются в Telegram.
- **TG → MAX:** long-polling `getUpdates` принимает сообщения группы Telegram и
  отправляет их в чат MAX; медиа скачивается из Telegram и загружается в MAX.
- **Анти-петля:** сообщение из MAX с меткой `[TG]:` в начале — это наша же
  пересылка, обратно не идёт; дополнительно каждый `message.id` запоминается
  на диске (`bridge_state.json`) и повторно не пересылается.
- Состояние (offset Telegram, окна дедупликации, флаг первого старта) переживает
  перезапуск.

## ⚠️ Заметки

- Не держите локальный экземпляр и серверный одновременно на одном токене —
  Telegram вернёт `Conflict`, а MAX словит конфликт сессий.
- Не коммитьте `.env` и `bridge_state.json` (уже в `.gitignore`).
- Для стабильной работы MAX-соединения важно корректно отвечать на серверный
  heartbeat (opcode 1) — не порождая новый запрос в ответ на ответ сервера.
